HOW SHOPAGENT WORKS

一位主客服，三位专业助手

Agent 是负责理解和处理问题的助手。工具模块负责查数据、做计算；两者不是一回事。

当前是原文架构的本地 MVP：真实模型处理问题，商品、订单和活动使用示例数据。公网链接与真实店铺尚未接入。
顾客提问 → 主客服分派 → 专业 Agent 查询工具 → 主客服汇总答复

复杂问题怎么协作？

例如：“推荐 200 元以内的降噪耳机，查黑色库存，再算优惠价。”

  1. 导购 Agent 根据预算筛选候选商品。
  2. 商品 Agent 查候选商品的黑色库存。
  3. 导购 Agent 查询活动，调用工具计算有货商品的优惠价。
  4. 主客服汇总，各步结果可以在对话的“Agent 协作记录”中查看。

Planning 是主客服拆分任务的职责，本版没有额外设立第五个 Agent。ReAct 指专业助手循环“查工具 → 看结果 → 决定下一步”。

现在能做什么？

查商品、比较店内标价、核实库存、按预算导购、查优惠、查本人订单与物流、生成待确认退货草稿、转人工并在原会话收到回复。

优惠是示例活动；退货不执行真实退款。停用某个工具模块后，相关查询会不可用，其他独立模块继续工作。

商品管理

政策与优惠

先保存草稿，核实后发布。过期内容和停用活动不会提供给客服。

店铺信息与 AI 调用额度

按北京时间每天统计。一次咨询可能调用模型多次；失败的调用也占额度。这不是金额预算。暂停或用完额度后仍可联系人工；规则测试模式不调用模型。

顾客咨询与人工回复

回复保存到顾客原会话。顾客点击“查看客服回复”查看；没有短信或邮件通知。

数据保留与运行监控

默认不清理。启用后每小时检查一次，分批删除无有效凭据且全部工单已关闭的过期访客咨询。每批最多200个会话，不清理正式账号、商品或政策。

最近24小时运行事件

错误类别与时间，不含顾客内容。需手动刷新，没有短信或邮件告警；没有事件不代表系统始终健康。

模型设置 · DeepSeek 等服务

地址和模型在 agent.toml，密钥仅在本地 .env。切换模式不会更改业务数据。

技术模块 · 启停和版本切换

这些是数据工具模块，不是 Agent。运行中停用只影响相关能力；版本切换等待旧请求完成。
