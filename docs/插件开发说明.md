# 插件开发与独立运行

一个业务插件包含 service.py、自己的初始化/仓库、参数模型和 TOOLS。它不导入其他业务域的实现，不直接读取其他域数据库；需要订单或政策时通过 plugins/client.py 调宿主内部接口。

## 接入步骤

1. 在 `shopagent/plugins/<name>/` 创建 Python 包和 `service.py`。
2. 参数模型继承 `StrictModel`，添加类型和约束。身份不放在参数中，使用请求的 identity。
3. 实现 `initialize()`；使用自己的数据库名，初始化只插入缺失数据、不覆盖用户记录。
4. 实现 `async def execute(params, request)`；业务失败抛 BusinessError。
5. 定义 `TOOLS = {"工具名": (参数模型, execute, "工具说明")}`。
6. 将模块路径和依赖加入 settings.py 的 PLUGINS 白名单。当前已有 demo.echo 示例，可先复制它。
7. 重启宿主读取一次白名单。管理员启用时，运行时完成进程启动、manifest 校验和能力注册；无需新增宿主 API 路由。
8. 通用 `/tools/invoke` 调用能力。若需要聊天自动理解新业务，还需在 ModelProvider 中增加意图识别，这与插件注册是两层职责。

## worker 独立接口

- GET /health：就绪状态、插件 ID、版本。
- GET /manifest：依赖、契约版本、命名空间工具和输入/输出 Schema。
- POST /invoke：参数、身份、request_id、deadline；必须带服务 HMAC 签名。

插件独立启动时使用宿主提供的服务密钥和 HOST_URL，分别置于 `SHOPAGENT_INTERNAL_KEY`、`SHOPAGENT_HOST_URL`。通常不需要手动运行，注册管理器会自动传入环境并分配端口。独立测试可导入本插件 initialize 和业务函数，或创建专用测试环境启动 worker。

## 热插拔范围

核心约束：一个宿主实例；不支持跨机器注册；动态接入只接受本地预配置白名单；停止插件不会删除数据。

每个工具请求在当前进程对象上记录在途数。停用先移出可用表，已有请求保留进程引用并执行完；升级先启动新进程再原子替换可用表，旧进程排空。依赖方排空期间仍保留被依赖模块。

健康检查失败、契约不兼容时接入被拒绝并关闭候选进程，已有版本保留。兼容版商品样例见 product/service_v2.py。其他模块 1.1.0 是相同实现的版本替换演示，若要部署新业务实现需增加明确的版本到代码路径映射，不能仅修改版本号。

共享的 ToolResult.data 是通用 JSON 载荷，当前按调用方的业务结构读取；更强的逐工具输出 Schema 和跨版本迁移属于后续强化。数据库迁移不参与在线版本切换。

本机服务使用身份签名、端口回环绑定、用户归属校验。不要将演示默认账号或这些接口直接公开到互联网。
