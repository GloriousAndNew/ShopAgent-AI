# ShopAgent AI：上线 MVP 的目标与现状

更新：2026-10-09。用户明确目标为上线使用，因此不能再把本机 Mock 演示作为最终交付。

## 这个产品是给谁用的

商家把商品、常见问题、配送及售后资料导入后台。顾客打开一个客服网页，用自己的话问问题，AI 查找资料并回答；无法确认时告知顾客并创建待处理咨询，商家在后台查看并回复。

例如顾客问：“这款耳机适合打游戏吗，拆封后不满意可以退吗？”系统查询该商品的参数和适用售后政策，给出有依据的回答，而不是匹配几个固定关键词。

如果暂时没有真实店铺，可以先发布“示例店铺体验版”，但需要真实模型和公网访问，并明确示例数据属性。这样的体验版可用于测试用户反馈，不能声称已经对接真实商家订单。

## 当前版本能做什么、不能做什么

| 项目 | 当前本机原型 | 上线目标 |
|---|---|---|
| 访问 | 仅当前电脑，127.0.0.1 | 其他人的电脑和手机可以通过 HTTPS 地址访问 |
| 理解问题 | DeepSeek Agent 已接通，通过有限样本实际问答 | 调用真实模型理解日常表达，保留参数与权限校验 |
| 回答来源 | 自动生成的示例商品及模拟政策 | 商家维护的资料；示例体验版需明确标识 |
| 内容维护 | 没有面向商家的资料上传/编辑页面 | 后台导入商品、维护政策和 FAQ、查看导入错误 |
| 顾客入口 | 公开演示账号 | 独立咨询入口；涉及私有订单时另验证顾客身份 |
| 人工处理 | 本机已补充管理员回复及顾客查看；尚未公网验证 | 商家能查看咨询并在网页中回复，顾客能看到答复 |
| 上线运营 | 没有公网部署和运营保障 | 服务部署、密钥配置、持久存储、限流、费用上限、日志和备份 |

现有 69 项测试验证的是原型业务及插件边界，不等于真实模型质量、公网部署或线上商用验收。

## 第一版范围：独立客服网页，店铺资料情况待确认

用户已选择独立客服网页，通过链接分享给顾客。先以单店铺上线：

1. 顾客进入咨询页面，能直接开始商品和政策咨询。
2. 商家登录后台，可以导入/编辑商品、政策和 FAQ，查看资料是否已生效。
3. 真实模型根据检索证据回答，展示对应商品与引用；证据不足时澄清或拒答。
4. 顾客可以转人工；商家在后台查看并回复，顾客能恢复该咨询并看到答复。
5. 网页有可从外部网络访问的 HTTPS 地址，并通过手机验证。
6. 商品、知识、模型、工单保留独立接口和插件启停能力；插件管理只有商家管理员能使用。

如果选择接入已有电商网站或平台店铺，需要先检查其允许的接入方式、身份机制和实际 API 权限，再确定上线工作。不以浏览器打开一个网页替代平台正式接入。

没有真实订单 API 时，上线版隐藏示例订单和自动售后提交入口。真实订单查询、退款及取件不能用模拟结果替代；这些能力在获得业务接口后增加。

## 实施顺序

1. 确认顾客入口、资料来源及第一版用户，冻结上线功能范围。
2. 调整顾客页和商家后台，明确演示模式与上线模式；上线配置禁止公开演示管理员密码。
3. 增加资料导入及版本管理，将生成样本与商家数据分开。
4. 接真实模型，支持自由问答、多轮澄清和证据引用；保存质量评测与失败样本。
5. 完成人工咨询回复闭环及顾客侧查看，形成真正可用的人工兜底。
6. 增加线上配置、流量/费用控制、存储与备份、部署脚本。
7. 配置模型及托管环境，在实际环境验证公网 HTTPS、重启持久化、权限和正常/异常问答。

公开上线需要一个模型服务和可运行后端的托管环境。具体服务选择、账户及费用由用户确认，密钥在本地或托管平台的秘密配置中填写，不发送到聊天中。

## 上线完成的判据

- 外部网络和手机可访问 HTTPS 服务，而非仅在本机打开页面。
- 实际调用真实模型；不能用 Mock 结果声称已接 AI。
- 后台修改商品或政策后，顾客可以查询到已发布的新版本。
- 与店铺资料一致的典型咨询、无证据问题和多轮澄清通过实测。
- 顾客转人工后，商家可以回复，顾客可以看到回复。
- 没有演示管理员账号暴露；顾客之间的数据与会话隔离。
- 密钥不出现在网页、代码仓库或返回结果中；调用失败和超额可控。
- 服务重启后资料与咨询保留；有可执行的备份恢复步骤。

当前状态：DeepSeek 真实 Agent 已在本机启用，商品、政策、库存、多轮指代及典型权限边界已完成真实模型实测，见《DeepSeek真实模型验证记录.md》。当前数据仍为示例；商家资料维护、更广泛模型质量评测、公网部署和线上验收仍未完成。
