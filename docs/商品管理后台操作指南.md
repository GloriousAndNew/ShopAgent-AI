# 商品管理后台操作指南

当前已实现商品管理；政策管理、正式账户、公网部署和真实订单接入继续按上线步骤推进。

## 打开后台

1. 打开 http://127.0.0.1:8000/；已有网页先刷新。
2. 用 Admin 登录，当前仍是示例密码 demo123。
3. 点击“商家后台”→“进入商品管理”。

商品管理是商品模块的能力。停用商品模块时后台会提示不可用；订单等独立模块不因此停止。普通买家不能修改商品，即使绕过网页直接调用工具也会被拒绝。Agent不会获得这些管理工具。

## 三种商品状态

| 状态 | 顾客能否查询 | 用途 |
|---|---|---|
| 草稿 | 不能 | 资料待核实、未发布 |
| 已上架 | 可以 | 客服可搜索、查询详情、库存和推荐 |
| 已下架 | 不能 | 保留原资料，暂时停止展示 |

下架影响后续查询；不会删除历史聊天中的已展示卡片，也不会修改既有订单。已经在处理中的咨询可能仍保留此前查到的资料，不能把下架解释成撤回所有历史答复。

这些仍不是实际店铺商品。请核实名称、规格、价格、库存与未知字段后再决定上架。政策草案没有导入或发布。

重复点击“导入10款示例草稿”会提示编号已存在，不会覆盖已有商品；查看或修改它们请使用“编辑商品”。

## 新增商品

1. 点击“＋ 新增商品”。
2. 编号使用P加3位数字，例如P111；编号不能与已有商品重复，编辑后不能改编号。
3. 填名称、分类和售价。网页金额单位是元，例如189.00；后台保存为18900分。
4. 填规格和说明；没有核实的品牌、保修月数留空，未提供的参数填在对应字段，客服不应猜测。
5. 设置颜色或规格及库存，每种分别填写，0表示缺货；同一商品各颜色使用同一标价。
6. 默认保存为草稿。虚构资料保留“示例资料”勾选；商家真实录入资料应由商家确认来源。
7. 点击“保存商品”，在列表中检查结果。

支持最多20种颜色或规格。当前没有图片上传、每SKU不同售价、平台实时同步、预留库存或下单扣库存功能。网页管理的是资料，不是交易系统。

## 修改价格与库存

1. 搜索商品名称或编号，点击“编辑商品”。
2. 修改售价或对应颜色库存，检查其他颜色是否保持正确。
3. 点击“保存商品”。商品状态保持表单中所选状态，已经上架的商品保存后可被后续查询读取。
4. 若提示“商品已被修改”，刷新列表并重新打开编辑，核对后再保存。不要用旧页面强行覆盖他人的修改。

新增、编辑和状态变更会在商品模块内记录操作人、时间和前后资料。当前没有单独的审计浏览或一键撤销页面。

## 上架与下架

资料检查后点击“上架”；暂时停止展示时点击“下架”。也可在编辑表单中选择状态再保存。

草稿和下架商品不对普通顾客提供搜索、详情、库存或比价结果；导购候选也从上架商品中筛选。上架操作不会发布店铺政策或启用真实支付。

## 批量导入

有两种方式：

- “导入10款示例草稿”：读取项目中固定的资料包，先预览。
- “导入JSON文件”：选择本地商品JSON，先检查格式和逐行校验结果。

预览不写入。只有点击“确认导入为草稿”才提交；即使文件写了上架状态，批量导入也会统一存为草稿。

一个批次最多100款；网页文件最多512KB。编号重复、价格无效、颜色重复或某行错误时，整批不写入，不会留下半批商品。再次导入已有编号时不覆盖。网络结果不明时先查询编号，核对是否已写入，不要盲目重复提交。

支持之前生成的资料包格式，也支持下面的简化格式：

```json
{
  "products": [
    {
      "product_id": "P111",
      "name": "商家待核实商品",
      "category": "配件",
      "price_fen": 9900,
      "noise_cancel": false,
      "description": "填写已核实的说明",
      "status": "draft",
      "simulation": true,
      "skus": [
        {"color": "黑色", "stock": 10},
        {"color": "白色", "stock": 0}
      ]
    }
  ]
}
```

JSON金额使用分，9900表示99元；库存必须是非负整数。不要把JSON金额99误当成99元。
