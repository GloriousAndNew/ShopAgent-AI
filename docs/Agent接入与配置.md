# 从演示客服到真实客服 Agent

更新：2026-10-09。

完全没有模型账号的新手，可以先读 [第一次接通真实Agent](第一次接通真实Agent.md)，其中提供可选的 DeepSeek 配置样例；采用前请核对平台当前可用模型。

## 已经加入什么

项目现在支持 **1 个客服 Agent 调用多个独立业务模块**。

以前：固定规则把问题分到一种业务，然后输出固定回复。

现在：真实模型理解问题，自主选择本轮可用的工具；程序执行查询，把结果交给模型，模型可以再查询其他工具，最后组织答复。例如同一问题可以同时查询耳机商品和拆封退货政策。Agent 可以参考最近 12 条会话消息继续咨询。

模型接入代码和管理员切换入口已实现。没有配置账号与密钥时，默认仍运行演示模式，不会产生模型调用费用。**接口测试通过不等于真实模型已经接通。** 当前商品、订单及政策仍为示例数据，也尚未公网部署。

## 你要准备的三个东西

在你选择的模型服务控制台中获得：

| 项目 | 含义 | 放在哪里 |
|---|---|---|
| API 基础地址 | 程序访问模型的入口，通常以 `/v1` 结尾；以服务官方文档为准 | `agent.toml` 的 `base_url` |
| 模型名称 | 控制台中的确切模型名称，必须支持工具调用/function calling | `agent.toml` 的 `model` |
| API 密钥 | 调用凭据，可能产生费用 | 本地 `.env`，不要发给聊天或放进网页 |

请先告诉开发助手服务名称，再核对该服务官方接口。不同服务的账号、地区可用性、收费及工具调用能力需要分别确认；尚未替你选择或购买服务。

## 手把手配置

1. 在项目文件夹找到 `.env.example`，复制一份，重命名为 `.env`。不要变成 `.env.txt`。
2. 用 VS Code 打开 `.env`，只在自己电脑里将 `your-api-key` 改成自己的密钥，保存。这个文件被 Git 忽略。
3. 打开项目根目录 `agent.toml`，填写 `base_url` 和 `model`。不要在这里填写密钥。
4. 选择协议：支持 Chat Completions 工具调用的服务填写 `protocol = "chat_completions"`；使用 Responses 的服务填写 `protocol = "responses"`。
5. 暂时保持 `mode = "mock"`，双击“启动ShopAgent.cmd”。已有服务可以继续运行，不必重启。
6. 登录管理员，打开“模块管理”，找到“客服 Agent”，点击“启用真实 Agent”。配置缺失会提示原因，保持演示模式。
7. 返回客服对话，提问：“找两百元以内的降噪耳机，再看看拆封后退货有什么条件”。核对商品卡片、政策引用和处理记录。
8. 如果需要让服务下次启动也使用 Agent，把 `mode` 改为 `"llm"`。管理员页面的切换只对本次运行生效，不会修改文件。

示意配置（尖括号内容要换成控制台给出的值）：

```toml
[agent]
mode = "mock"
protocol = "chat_completions"
base_url = "<服务官方给出的HTTPS基础地址>"
model = "<支持工具调用的模型名称>"
max_steps = 6
max_tool_calls = 8
max_output_tokens = 1200
timeout_seconds = 60
```

本实现采用模型工具调用流程：模型提出调用，应用执行工具，再把结果返回给模型。两种协议的工具结构分别适配。依据：[OpenAI 官方 Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。该文档指出 GPT-6 Astra 和 GPT-6.1 Sol 的工具调用需要 Responses；不要把任意模型名称填入 Chat Completions 后假设兼容。其他服务的兼容性仍需要实际测试。

## 如何判断接通

- 页面切换成“真实模型 Agent”只表明已启用接口配置。
- 本地配置显示完整，只表明参数与密钥存在，不证明账户权限、额度或模型兼容性。
- 真正接通需要实际咨询成功，返回 `mode = llm` 且 `model_used = true`；处理记录显示成功查询工具，商品及引用与结果一致。
- 问候可能不需要工具；订单、价格及政策咨询应有相应工具查询记录。
- “转人工”可以直接创建咨询，即使模型不能使用。这种请求不调用模型，`model_used = false`。

## 权限与调用边界

- 只有管理员可以启用、关闭 Agent。切换不重启业务插件，已开始的请求继续使用原实例。
- 每轮只提供健康插件的查询工具与售后草稿工具；插件中途停用或切换时，宿主再次检查快照与可用性。
- 模型不能选择用户身份，工具使用登录用户身份；不能操作管理员功能、执行命令、调用扩展演示插件或确认售后提交。
- 草稿确认凭据不会发给模型，也不保存到聊天历史。顾客仍需要点击确认按钮。
- 每轮最多 6 次模型请求、8 次工具调用，整个请求默认 60 秒；Agent 每个实例最多同时执行 4 轮咨询。模型服务失败不自动重试，不静默改用演示回复。
- 工具返回数据与历史内容仍可能包含提示注入，提示词要求模型将其视作数据；权限与工具白名单由程序强制执行。
- 模型最终标为事实回答但本轮没有成功资料时，程序改为无法核实。该检查不能证明每句话都正确；有资料时仍可能误解，必须通过真实模型评测。
- 政策仍按关键词检索，可由 Agent 改写关键词；尚未加入向量检索。业务数据尚未接真实店铺。
- 当前限额是单轮与单实例控制，**不是账户月度费用上限，也不是公网防滥用方案**。上线前仍需要访客身份、限流、日额度、资料后台、部署和实际验收。

启用真实模型后，顾客问题、最近会话和必要的工具结果会发送到所选模型服务；部署真实店铺前需要确定资料范围与告知方式。密钥保留在服务端，管理员接口只返回配置状态。

## 出错时怎么处理

| 提示 | 下一步 |
|---|---|
| 配置不正确/未配置 | 检查基础地址、模型名称、`.env` 文件名和内容 |
| 认证失败 | 检查密钥所属服务及账号权限 |
| 额度不足/请求过多 | 在模型服务控制台查看额度及请求限制 |
| 接口请求失败 | 核对协议、基础地址与模型工具调用能力 |
| 格式不符合/未按要求答复 | 核对协议兼容性；保留问题作为模型质量评测样本 |
| 调用达到上限/超时 | 缩小问题范围，或转人工；不要盲目提高上限 |

## 代码位置

- `core/agent_config.py`：配置读取、基础地址和参数验证。
- `core/llm_provider.py`：可替换的模型 HTTP 适配器。
- `core/llm_agent.py`：工具循环、资料收集、上限和输出检查。
- `core/orchestrator.py`：演示/Agent 模式切换。
- `core/registry.py`：独立插件的工具契约、快照与权限调用。
- `tests/test_agent.py`：模型响应桩、HTTP 协议、权限及真实插件联调测试。

模型适配器可以替换；当前 Agent 核心是进程内实例，业务插件仍是独立进程。这里没有把一个模型实例描述成多个独立 Agent，也没有增加新的部署服务。
