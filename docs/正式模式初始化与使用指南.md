# 下一步已完成：正式账户、生产模式与示例数据隔离

当前仍未上线公网。原来8000端口的演示系统继续保留，不清空商品、会话和DeepSeek配置。

## 1. 开发模式和正式模式是什么

| 内容 | 原开发演示 | 新正式模式 |
|---|---|---|
| 数据目录 | `data` | 默认`data-production`，独立保存 |
| 管理员 | Admin / demo123 | 你自己在本机初始化，无默认密码 |
| 初始资料 | 演示商品、政策、订单、优惠 | 空商品、空政策、空优惠，不自动复制示例 |
| 业务模块 | 完整演示 | 商品、政策、导购；订单/物流/售后/演示模块禁止启用 |
| 示例资料 | 可以演示 | 可以保存明确的示例草稿，但不能发布或被顾客查询 |
| 默认本地端口 | 8000 | 正式启动脚本用8001，仍只监听本机 |
| 模型配置 | agent.toml / .env | agent.production.toml / .env.production，或明确指定环境变量 |

“正式模式”指正式资料和身份的运行规则，不表示已经部署到公网，也不会自动证明商家录入的资料真实。

## 2. 你现在只需先设置自己的管理员

1. 在项目文件夹双击 **初始化正式管理员.cmd**。
2. 输入账号，推荐`owner`。规则：3至40位，英文字母开头，可含数字、横线、下划线；不能用alice、bob、admin或guest_开头。
3. 输入密码，至少12位，包含字母和数字。输入时不会显示字符，这是正常的。不要在聊天中发送密码。
4. 再输入一次密码，看到“正式管理员已创建”即完成。

脚本只能创建首个管理员；重复运行不会覆盖账号或重置密码。当前没有密码找回或改密码界面，请自行妥善保存。不要删除生产库来随意重设密码，已有资料和咨询也在里面。

初始化需要你在本机交互式窗口输入，程序不接受命令行或管道密码。当前没有替你创建真实管理员；自动化测试使用的是隔离测试库中的测试账户。

## 3. 启动正式模式

双击 **启动正式ShopAgent.cmd**，然后打开：

- 顾客：http://127.0.0.1:8001/customer
- 商家：http://127.0.0.1:8001/merchant

输入自己的正式账号和密码。初始商品列表为空，这是隔离成功的表现。没有初始化管理员时，服务会拒绝启动并提示先初始化。

停止时双击 **停止正式ShopAgent.cmd**。原来的启停脚本仍管理8000端口的开发演示，不会同时清空或停止另一份库。

## 4. 录入真实资料

1. 商品管理中新建商品，核实名称、价格、规格与颜色库存，取消“示例”勾选，再上架。
2. 政策管理中新建政策，填写商家确认的文字与关键词；退货政策的编号仍为return。核实执行规则，取消示例标记后发布。
3. 有真实优惠才新建活动，检查范围、金额门槛和北京时间有效期，取消示例标记后发布。

示例标记未取消，正式模式会拒绝发布；公开查询还会再次排除示例内容。取消标记是商家作出的确认，程序无法替你核验价格、资质或政策真实性。未知参数仍留空并明确说明，不靠模型猜测。

原10款虚构资料包不自动搬进生产库，正式界面隐藏示例资料包入口。手动JSON导入仍只能先保存草稿，不直接上架。

## 5. 正式模式如何继续使用DeepSeek

开发配置保持原样。生产配置分开，避免无意沿用开发参数或密钥。

1. 在本机把已验证的`agent.toml`复制为`agent.production.toml`，核对模型名称、地址和调用上限。
2. 将生产使用的密钥填写在本地`.env.production`的`SHOPAGENT_MODEL_API_KEY=`之后。可选择继续使用自己的现有账号；不要发给我或上传到仓库。
3. 重启正式服务，查看模型状态并实际提问验证。

没有`agent.production.toml`时默认规则测试模式，可先维护资料和体验人工流程；这时不是DeepSeek回答。配置为llm但密钥缺失时会拒绝模型连接，不会偷偷读取开发`.env`。

如果明确设置了`SHOPAGENT_MODEL_API_KEY`或`SHOPAGENT_AGENT_CONFIG`环境变量，它们优先于默认文件，操作前要确认变量来自哪一套环境。生产密钥和生产数据已加入Git忽略规则；`agent.production.toml`仅放普通参数，不要把密钥写进去。

## 6. 目录保护如何起作用

每个数据目录会有`.environment.json`环境标记。生产模式拒绝开发目录、旧的未标记非空目录或development标记；开发模式也拒绝production标记的目录。

不要修改标记、复制整个演示库或把`SHOPAGENT_DATA_DIR`指向旧data来冒充迁移。需要迁移时，从审核过的业务资料按管理后台逐项录入。服务器启动还会检查是否存在示例账号、示例密码或缺少正式管理员。
