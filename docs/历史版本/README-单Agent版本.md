# ShopAgent AI · 电商客服 MVP 开发中

**当前目标已调整为上线 MVP：独立客服网页，通过链接分享给顾客。** 上线范围及剩余工作见 [上线目标与差距](docs/上线MVP目标与差距.md)。下面描述的是现有本机原型，真实模型 Agent 已在本机接通 DeepSeek，并完成典型咨询与权限实测；公网部署尚未完成。

**真实模型已接通：** DeepSeek `deepseek-flash` 已完成本机实际问答与权限验证，当前启动模式为 `llm`。详情见 [真实模型验证记录](docs/DeepSeek真实模型验证记录.md)。密钥不随项目交付；换电脑配置见 [新手配置指南](docs/第一次接通真实Agent.md)。商品与政策仍为示例，尚未公网部署。

这是单店铺、本机运行的电商客服原型。当前已启用 **DeepSeek 真实模型 Agent**：模型理解问题、选择工具并根据结果组织回复。业务数据仍为示例，不执行支付、退款或物流取件。真实咨询会调用模型接口，费用以服务平台账单为准。

已有能力：商品/指定 SKU 库存、用户自己的订单与物流、版本化政策引用、售后草稿与确认提交、人工咨询及管理员回复、会话恢复、独立进程插件启停、在途排空、兼容版本切换与回退。

## 新手启动

1. 双击项目中的 **启动ShopAgent.cmd**。
2. 等终端显示 `Application startup complete`。
3. 浏览器打开 [ShopAgent 工作台](http://127.0.0.1:8000)。
4. 选 alice、bob 或 admin，密码都是 `demo123`。

当前模式为真实 Agent，启动需要本地密钥。若在新电脑上只体验演示规则，将 agent.toml 的 mode 改为 mock。

第一次缺少环境/依赖时，启动脚本会创建项目 `.venv` 并安装 requirements.txt，需要联网。已有环境和依赖时不会重复安装。数据自动初始化，不覆盖已产生的申请和会话。

停止：双击 **停止ShopAgent.cmd**，或者回到启动窗口按 **Ctrl+C**，等待停止后再关闭窗口。主程序会关闭自己管理的全部插件。停止脚本使用本次宿主的随机本机凭据，不会按进程名批量杀进程。请勿直接在任务管理器强杀宿主，以免独立插件成为残留进程。

当前实现用 Python 3.13 验证。支持范围为 3.12–3.13，Windows 启动脚本默认调用电脑已有的 3.13。裸命令 `python` 在这台电脑指向 3.7，请使用本项目 `.venv` 路径。

## 从终端启动

在项目根目录的 PowerShell 执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -X utf8 -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m shopagent.run
```

已有 .venv 可以跳过第一条。端口 8000 被入门练习或其他服务占用时，先停旧服务，或者使用：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m shopagent.run --port 8001
```

然后访问 `http://127.0.0.1:8001`。只开一个宿主实例；不使用 `--reload` 或多个 Uvicorn worker 管理插件。

## 建议第一次体验的顺序

登录 alice 后：

1. 问 `200 元以内的降噪耳机`，看到商品卡片。
2. 问 `第二款黑色还有货吗`，验证商品指代和 SKU 库存。
3. 问 `我的订单`，再问 `订单 O1001 到哪了`。
4. 问 `查订单 O2001`，应提示订单不属于当前用户。
5. 问 `拆封以后能退吗`，查看政策文本和版本。
6. 问 `申请退货 O1002，已拆封，质量问题耳机没声音`。
7. 核对草稿，点“确认提交模拟申请”。只创建待审核申请，不执行退款。
8. 问 `售后进度`，看到自己的售后单。
9. 问 `转人工`，生成咨询；用另一浏览器或标签页登录 admin，在模块管理页底部回复。买家在原会话点击“查看客服回复”，会看到标明人工来源的消息。回复持久化保存，没有短信或邮件通知，不保证即时回复。

演示订单：Alice 为 O1001–O1005，Bob 为 O2001–O2005。尾号 2 和 5 为已签收，可按模拟规则演示申请。种子订单签收时间为数据库首次创建时刻，超过 7 天会按规则拒绝申请，并非程序故障。

演示模式使用预设规则；当前真实 Agent 使用模型理解自由表达，仍可能出错。缺少必要资料时应澄清或转人工，请核对工具处理记录和政策引用。现在可在管理员页面启用真实模型 Agent：它根据问题选择多个工具，查询后组织答复。配置步骤见 [Agent 接入与配置](docs/Agent接入与配置.md)；未配置时仍使用演示规则。宿主仍负责权限、参数和确认校验。

## 模块独立和热插拔

退出买家，登录 admin，点击“模块管理”：

- 物流停用后，商品和订单仍可查询；恢复后物流重新可用。
- 关闭订单或政策时，若有依赖模块正在开启，默认拒绝；“级联停用”按先依赖方、后被依赖方的顺序执行。
- 版本切换创建新 worker，校验健康与工具 Schema，再把新请求切过去，旧进程排空后退出。可切回 1.0.0。
- 商品 1.1.0 使用真实的兼容样例实现 `service_v2.py`，查询结果多一个 `catalog_build` 字段；其他插件的 1.1.0 当前使用相同业务实现，仅用于演示进程替换。
- “扩展演示”默认关闭；启用后点“测试扩展能力”，无需添加宿主 API 路由。
- 模块进程崩溃后变为 failed，其他插件保持服务；管理员可重新启用。

这是本机白名单插件系统，不支持从互联网安装任意插件或通过聊天执行程序。新增自定义插件步骤见 [插件开发说明](docs/插件开发说明.md)。更改白名单配置需要重启宿主一次，随后可以运行时注册/启停这个准备好的插件。

核心认证、会话、宿主 API 不在热卸载范围；不兼容数据库迁移需要维护。当前没有分布式多宿主协调、灰度流量或任意历史代码包部署器。

## 目录

```text
shopagent/app/            登录、聊天、管理 API
shopagent/core/           模型适配、Agent 工具循环、Mock 路由、会话与插件管理
shopagent/contracts/      请求、身份、结果和 manifest 契约
shopagent/plugins/        每个业务域独立实现及 worker
shopagent/web/            聊天页及管理页
data/                    自动生成；每个模块拥有自己的 SQLite
tests/                   业务、隔离、确认、故障与热插拔验收
docs/                    计划、学习资料、使用与插件开发说明
learning_examples/       入门练习，和正式应用分开
```

`data/` 不是源代码，不提交版本库。core.db 存用户、会话、令牌哈希及工单；其他插件只读写自己数据库。插件间通过带签名的 HTTP 接口调用，不直接访问别人的表。

## 验证

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q --junitxml=test-results\acceptance.xml
```

验收会在临时目录和临时端口创建自己的数据及宿主，不修改你的正常演示数据。包含独立插件启动、HTTP 联调、并发重复确认、依赖级联、真实进程崩溃和宿主重启验证。

故障日志：`data/logs/`，按插件及版本分文件。主程序输出 request_id、工具名、版本及耗时。接口文档：`/docs`；订单及工具 API 需要在请求 Header 加登录返回的 `Authorization: Bearer <token>`。

## 已知边界

只用于本机教学演示，绑定 127.0.0.1；默认演示账号和密码公开，不能直接当成线上商用系统。没有真实支付、退款、物流 API、云模型调用、向量检索、SSE 文本流或高并发部署。宿主认证使用可撤销且有过期时间的不透明令牌，而不是 JWT；对于这个本机单宿主版本可减少依赖。

真实模型和真实业务 API 接入属于后续阶段，必须继续保留代码中的身份、规则、确认和幂等校验。本次不复制原始材料中的收益、上线规模或性能数值。

项目架构参考：[FastAPI 生命周期](https://fastapi.tiangolo.com/advanced/events/)、[Pydantic 模型校验](https://docs.pydantic.dev/latest/concepts/models/)、[HTTPX 异步客户端](https://www.python-httpx.org/async/)。实际实现及测量以本仓库为准。
