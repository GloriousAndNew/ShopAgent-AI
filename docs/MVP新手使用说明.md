# MVP 已经写好，先这样体验

这次准备的是正式应用，不再是第一天的练习接口。无需模型账号，无需服务器；运行在你自己的电脑上。

## 第一步：打开

双击项目文件夹中的 `启动ShopAgent.cmd`。黑色窗口保持打开，看到“Application startup complete”后，浏览器访问 `http://127.0.0.1:8000`。

若我本次留下的服务已经在运行，直接访问网页即可，不要重复启动；显示端口占用时先检查已有服务。

选 Alice，密码 demo123。你会看到客服页面、快捷问题和输入框。

## 第二步：查商品

点击“200 元以内的降噪耳机”。页面显示商品名称、价格和编号。点击某个商品的“查黑色库存”，或输入“第二款黑色还有货吗”。

这些资料来自商品模块的数据库。它们是生成的演示商品，不代表真实商家。

## 第三步：查订单和物流

点击“我的订单”。O1001 在运输中，O1002 已签收。点物流按钮，看模拟轨迹。没有预计时间会明确显示未知。

问“查订单 O2001”，看到无法查看。退出后换 Bob 登录，他能看 O2001，却不能看 O1001。这是用户隔离。

## 第四步：了解规则、申请售后

回到 Alice，先问“拆封以后能退吗”，查看政策引用。然后输入：

```text
申请退货 O1002，已拆封，质量问题耳机没声音
```

看到申请草稿，核对订单、原因、政策版本。只有点击“确认提交模拟申请”后才创建售后单；点击取消则不提交。申请状态为待审核，不扣款、不退款、不联系快递。

草稿确认有效期 15 分钟。会话历史不保存确认凭据，重新载入历史草稿时必须重新生成后才能确认。不要把历史卡片当作新的可提交申请。

## 第五步：看模块热插拔

退出后用 Admin 登录，点“模块管理”。

1. 停用物流。
2. 返回客服对话，问物流，看到不可用；查询商品仍正常。
3. 重新启用物流，恢复查询。
4. 商品模块从 1.0.0 切换到 1.1.0，再切回。主程序不用重启。
5. 启用“扩展演示”，点击测试扩展能力。

管理员没有自己的买家订单；验证买家物流时可以退出换 Alice。请注意退出不会重启宿主，也不会恢复你停用的插件。

订单被其他模块依赖，直接停用会被阻止。级联停用会连同物流和售后一起关闭；重新启用时先开订单，再开物流和售后。

## 第六步：理解一次处理过程

商品查询后展开“查看处理记录”，你能看到调用了哪个工具、是否成功、使用哪个插件版本。

程序大致按“网页发送问题 → 模拟路由识别需求 → 主程序验证 → 插件查自己的数据 → 返回结果 → 页面展示”工作。Mock 路由只是目前代替大模型的部分。

## 结束和继续学习

停止服务：双击 `停止ShopAgent.cmd`，或在启动窗口按 Ctrl+C，等待停止。不要直接强制结束宿主进程。

建议按顺序读代码：`model_provider.py` 看识别需求 → `product/service.py` 看商品查询 → `orchestrator.py` 看调用工具 → `registry.py` 看启停进程。具体路径和运行方法见根目录 README。
