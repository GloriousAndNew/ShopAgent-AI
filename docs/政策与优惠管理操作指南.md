# 政策与优惠管理：不用改代码的操作步骤

更新日期：2026-10-09。这是本地 MVP 操作指南；当前商品和订单仍为示例，尚未上线公网。

## 1. 先理解三个词

| 名称 | 你可以怎样理解 |
|---|---|
| 草稿 | 写在笔记本里的内容，顾客还看不到 |
| 发布版本 | 你已确认的内容，客服查询时可以使用 |
| 当前有效 | 已发布，而且已到开始时间、未到结束时间 |

**保存草稿不等于发布。** 修改已有政策或活动时，原发布版本继续使用，直到你发布新版本或停用。

## 2. 从哪里进入

打开 http://127.0.0.1:8000/ → 登录 Admin（本地示例密码 `demo123`）→ 商家后台 → 政策管理 / 优惠管理。

## 3. 编辑一份政策

1. 进入政策管理，选择“配送与发货”等草案，点击“载入资料包草案”。这一步只填入表单。
2. 阅读内容，把“商家待填写”的信息换成自己确认过的资料。没有确认的事情就明确写“暂无法确认”。
3. 检查标题和检索关键词。关键词用空格隔开，例如 `发货 配送 运费 快递`；当前是关键词检索，还不是向量检索。
4. 开始、结束时间按北京时间填写；普通政策可留空，代表不设这项时间限制。结束时刻到达后不再有效。
5. 点击“保存草稿”。先通过“查看当前发布内容”核对旧内容，再决定是否点击“发布草稿”。
6. 不再适用的政策点击“停用”；它仍保留草稿和历史记录，但不会提供给新查询。
7. “历史版本”可以查看过去发布的文字和版本。旧会话保留当时引用，不会自动改写。

资料包有 **11 份草案**，不会批量自动发布。当前已通过网页把配送草案保存为草稿，原发布配送说明仍生效。其他草案可按上述步骤逐项载入和核实。

“示例政策”勾选表示内容尚未被真实商家确认。取消勾选只改变标记，不会证明内容真实，也不会把模拟订单变成真实订单。

## 4. 退货政策多了一组执行规则

选择“退货申请与完好检查”，编号为 `return`，页面会显示期限、起算方式、拆封人工核验和质量问题人工核验。

这些选项是程序用来判断申请的条件。发布时，系统会把它们生成规则摘要，附在政策说明中。期限等条件填写在规则选项中，补充文字不要再写相反条件；目前程序不能自动理解并排除所有文字矛盾。

- 新规则可以按签收次日、北京时间起算。
- 拆封申请可转人工核验，不一概拒退。
- 质量问题可以转人工单独核验，不套用非质量申请期限。
- 符合自动流程时仍只生成待确认草稿，顾客确认后保存模拟申请；不会执行退款。
- 已发布政策变化后，旧的未提交草稿需重新生成；已经提交的记录继续保留。

**当前本机仍保留旧演示退货规则，后台有提示。** 新草稿不会自动替换它。正式使用前，需要核实并发布适用的新政策。规则选项不是法律合规自动审核工具。

## 5. 新建一项优惠

1. 进入优惠管理，点击“新建优惠”。
2. 活动编号可填 `SHOP-OCT-90`，标题填能看懂的名称。
3. 填适用分类，或指定商品编号，如 `P101、P102`。两者都填时必须同时满足；都空表示不限。
4. 选择折扣或固定金额减免。折扣填 `90` 表示九折，`80` 表示八折；金额单位是元。
5. 最低商品原价小计填 `0` 表示无门槛，填 `199` 表示原价小计满199元才能用。
6. 填北京时间的开始、结束时间；发布优惠必须有有效期。
7. 保存草稿，核对后点击“发布活动”。未来开始的活动会显示“尚未开始”。
8. 活动不再适用就点击“停用”。停用后重启模块也不会自动恢复。

比如商品原价189元、九折、无门槛，试算金额是170.10元。程序从商品工具取标价，以整数“分”计算；折扣出现不足一分时向下取整。固定减免后的金额最低为0。

每次只按指定的一项活动计算，不叠加、不含运费，也不是支付页面或订单成交价。活动管理不会创建优惠券、锁库存或执行收款。仅有草稿的商品仍不能被顾客查询或试算。

本机沿用原有 `DEMO-EAR-10` 示例九折。网页验收产生的 `DEMO-NEW-90` 已停用，保留草稿供查看；它不能使用。

## 6. 出现问题怎么处理

| 提示 / 情况 | 怎么做 |
|---|---|
| 已修改，请刷新 | 另一个页面修改了相同资料；刷新并重新编辑，避免覆盖别人修改 |
| 不能发布过期内容 | 修改结束时间，保存草稿后再发布 |
| 发布后顾客查不到政策 | 检查有效期、关键词、是否停用；政策检索只返回匹配度最高的3条 |
| 优惠金额没变化 | 检查活动是否有效，分类、商品编号和原价门槛是否同时满足 |
| 对应模块停用 | 后台技术模块中启用政策模块或导购模块，再刷新 |
| 已发布内容和草稿不同 | 正常；只有发布新草稿后才替换当前版本 |

政策由政策模块存储在 `data/knowledge.db`，优惠由导购模块存储在 `data/recommend.db`。原来的 `data/policies/*.md` 保留为迁移来源，迁移后直接改这些文件不会更新客服回答。以后从后台维护。
