## 你要做的东西，用一句话解释

做一个网页客服：用户输入问题，程序理解他想查什么，再查询商品、订单、物流或售后规则，最后把结果告诉他。涉及售后申请时，必须由用户确认。

把它想成一家店：网页是前台，主程序是接待员，商品/订单/物流模块是各个部门，模型负责听懂问题。每个部门可以独立开门、关门或升级，这就是本项目要求的模块独立和热插拔。

开发顺序：

```text
会运行 Python
  → 用代码筛选商品
  → 浏览器能查商品
  → 明确模块接口
  → 数据存入数据库
  → 订单、物流、政策、售后
  → 聊天页与模型
  → 模块独立进程和热插拔
  → 验收与启动说明
```

## 当前已经有什么

已有：项目资料、开发计划、本套学习手册、入门练习，以及 `shopagent` 中可运行的 Mock MVP、独立插件热插拔、启动脚本和自动验收。

后续阶段：真实模型、真实商家 API、线上部署和向量检索。`learning_examples` 里的商品接口仍只是练习；正式应用通过根目录的启动脚本运行。

2026-10-09 检查你的电脑发现：

- VS Code 已安装。
- `py -3.13` 可以调用已有的 Python 3.13。
- 裸命令 `python` 目前指向 Python 3.7.7；本手册避免使用它。
- Python 3.13 的全局环境没有 FastAPI 和 Uvicorn；操作手册会指导你把它们装在项目虚拟环境里。

原计划推荐 Python 3.12；这套练习使用电脑已有的 3.13，减少重新安装的步骤。正式开发时统一使用一个版本，并验证、固定依赖。

## 每天怎么学

建议每天 60–120 分钟：20 分钟看对应知识，40–80 分钟动手，最后 10 分钟记录结果。零经验者先预留约 1–2 周打基础，再按原计划推进；进度以能完成任务为准。

今天做到 `hello.py` 能输出文字就有了第一个成果。若你还有精力，再跑通 `/health` 和 `/products`。不要把“第一天”理解为必须一天全部完成。

每次完成一关，记录：

```text
日期：
今天完成了什么：
运行的命令：
看到的结果：
我能解释的概念：
没有解决的问题：
下一步：
```

卡住时提供命令、完整报错文字和正在做的关卡。只发“运行不了”很难定位；如果报错中含密钥或账号信息，先删掉这些内容。
