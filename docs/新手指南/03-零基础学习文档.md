# 零基础学习文档：用电商例子理解编程

这份文档按项目需要讲概念。先读前 5 节并运行练习；数据库、模型和热插拔到对应开发关卡再学。不是让你今天背下所有名词。

## 1. 先分清文件、程序、终端和网页

代码写在 `.py` 文件里，保存后交给 Python 执行。终端用于输入“运行哪个文件”的命令。网页是用户看到的界面，后端程序负责查询和处理数据。

示例：你在网页输入“200 元以内的耳机”，网页把问题发给后端，后端查商品，网页显示结果。

| 词 | 用白话解释 | 本项目里的例子 |
|---|---|---|
| 文件 | 存文字或数据的东西 | hello.py、政策 Markdown |
| 目录/文件夹 | 将相关文件放在一起 | learning_examples |
| Python | 执行 Python 代码的工具及语言 | 运行商品筛选 |
| 终端 | 用文字命令操作程序的窗口 | PowerShell |
| 虚拟环境 | 一个项目自己的 Python 工具箱 | .venv |
| 依赖/包 | 别人写好、你可以使用的工具 | FastAPI |
| 前端 | 用户看见和点击的页面 | 聊天框、确认按钮 |
| 后端 | 接收请求并处理业务的程序 | 查询订单 |

练习：运行 hello.py、修改文字、保存后再次运行。你应该能说出是哪一个文件决定了输出。

## 2. 变量、数据类型和金额

变量就是给一份数据起名字：

```python
name = "降噪耳机"     # 字符串：文字
price_fen = 18900     # 整数：这里表示 189 元
in_stock = True      # 布尔值：只有 True 或 False
```

`=` 表示把右边的值交给左边的名字；判断相等用 `==`。`#` 后面是给人看的注释。英文引号、冒号和括号要照代码写，不要替换成中文标点。

本项目把钱保存为“分”的整数：189 元存 18900。这样程序计算时不用依赖浮点小数精度。界面展示时除以 100，例如 `f"{price_fen / 100:.2f}"` 将价格显示为两位小数。

练习：把练习中的耳机价格改为 20900，20000 的预算是否还能找到它？预期不能。

## 3. 字典和列表：怎么描述多个商品

字典是一组“字段名 → 值”的资料；列表按顺序放多份资料：

```python
product = {"name": "耳机", "price_fen": 18900}
print(product["name"])

products = [
    {"name": "耳机", "price_fen": 18900},
    {"name": "鼠标", "price_fen": 9900},
]
print(products[0]["name"])
```

`product["name"]` 取名称；`products[0]` 取第一件商品，因为 Python 的位置从 0 开始。花括号 `{}` 在这里表示字典，方括号 `[]` 在这里表示列表或取值。

练习：在 product_filter.py 的 PRODUCTS 中添加一个新商品。确保商品之间有英文逗号。

## 4. 条件、循环、函数：筛选为什么能工作

`if` 表示“如果满足条件才做”；`for` 表示“把每件商品依次看一遍”；`def` 定义可重复使用的一段步骤。

```python
def search_products(max_price_fen):
    results = []
    for product in PRODUCTS:
        if product["price_fen"] <= max_price_fen:
            results.append(product)
    return results
```

逐行理解：接收预算 → 建空结果列表 → 检查每件商品 → 不超预算就加入结果 → 返回结果。PRODUCTS 在练习文件前面已定义，单独复制这段而不定义 PRODUCTS 会报错。

`<=` 是“小于或等于”；`append` 是“往列表末尾加入一个元素”；`return` 把结果交给调用它的代码。缩进表示哪些步骤属于函数、循环和条件。通常每层缩进 4 个空格，不能随意删掉。

运行已有练习：

```powershell
py -3.13 -X utf8 .\learning_examples\product_filter.py
```

原始样本的预期：预算 200.00 元，输出 189.00 元耳机和 99.00 元鼠标，共 2 件。预算改成 10000 时只输出鼠标。

这一节的自测：你能解释如果把 `<=` 改成 `>=`，为什么筛选方向反了？答案：会选出大于或等于预算的商品。

## 5. 接口、HTTP 和 JSON

接口是程序提供的办事窗口：你按规定送参数进去，它按规定返回数据。HTTP 是浏览器与服务通信的常用方式；JSON 是一种常用的数据表达格式。

```text
GET /products?max_price=200
```

含义：查询商品窗口，传入最大价格 200。`GET` 用于读取；`POST` 常用于提交数据或执行操作。名称本身不能代替权限和确认检查。

响应示意：

```json
{"count": 1, "products": [{"id": "P001", "price_fen": 18900}]}
```

JSON 字段名和文字使用双引号；Python 中是 `True`，JSON 中是 `true`。遇到格式问题，先区分自己在编辑 Python 文件还是 JSON 文件。

常见状态码：200 成功；401 需要有效登录；403 没有权限；404 找不到；422 参数不符合要求；500 程序内部失败。参数错误应提示用户，程序内部错误需要查看后端日志。

练习：在第一天接口输入负数预算，查看 422；输入 50 查看成功但结果为空。空结果和报错不是同一回事。

## 6. 模块、插件和契约

模块是分工清楚的一组代码。商品模块查商品，订单模块查订单。`import` 让一个 Python 文件使用另一个文件提供的能力；学习例子中的接口调用商品筛选函数，就是一次简单分工。

契约是双方共同遵守的约定，例如输入必须有商品 ID，输出必须有状态和数据。Pydantic 帮你检查“字段有没有、类型对不对”。它不替你判断这个用户是否拥有订单，也不替你证明模型答案正确。

插件是能按统一约定接到宿主的模块。manifest 是插件说明书，列出插件名称、版本、依赖和能力。注册表是宿主当前可用部门的名单。

本项目的独立要求：自己的代码、数据和测试；跨插件只用公开接口；新增插件通过能力注册接入。仅仅建不同文件夹还不够。

练习：用纸写商品查询工具的输入和输出。输入：预算及关键词；输出：商品 ID、名称、价格、结果状态。先理解约定，再写代码。

## 7. 数据库与 SQL

变量中的数据通常随进程结束而消失；数据库把数据存下来。SQLite 可以使用一个本地数据库文件，适合这版原型，且不需要独立数据库服务器。[Python 官方说明](https://docs.python.org/zh-cn/3.12/library/sqlite3.html)

理解四种动作：新增 INSERT、读取 SELECT、更新 UPDATE、删除 DELETE。先学习新增和读取。

下面是 SQL 说明片段，不是 PowerShell 命令，不要粘到终端直接执行：

```sql
SELECT id, name, price_fen
FROM products
WHERE price_fen <= ?;
```

含义：从商品表取 ID、名称、价格，限制价格不超过参数。`?` 由 Python 的数据库调用传入真实预算；不要把用户输入直接拼到 SQL 文本里。

交易/事务是“一组关联变化一起成功或一起失败”。售后提交时，需要创建申请单和记录幂等信息；不要只写成功一半。

本关练习目标：将 3 个商品写入数据库，结束程序、重新运行、再查询，仍得到原商品。

## 8. 用户隔离、状态和幂等

用户隔离：A 登录后只能查询 A 的订单。不能因为用户输入了 B 的 ID 就相信他是 B。可信身份来自登录验证，订单工具也要验证订单归属。

状态：一件事情现在走到哪一步。例如售后从收集资料、草稿、等待确认到已提交，每步有允许的下一步。

幂等：同一次操作重复提交，业务效果仍只有一次。例如因为网络慢点两次确认，不能创建两张售后单。程序用幂等键、唯一约束和事务实现，不能仅靠按钮变灰。

练习目标：用 A 查 B 的订单失败；创建草稿后申请表未新增；重复确认得到同一个申请单号。

## 9. 模型、Agent、工具调用与 RAG

| 概念 | 本项目中的意思 |
|---|---|
| 大语言模型/LLM | 读懂文字、生成文字的服务，可能误解和编造 |
| 意图 | 用户想做什么，如查询订单或申请售后 |
| 工具 | 程序允许调用的业务函数，如查库存 |
| Agent | 结合问题、上下文与工具完成任务的程序 |
| 工具调用 | 模型建议“用这个工具、传这些参数”，程序校验后才执行 |
| Mock | 用预设结果模拟外部系统，便于先开发流程 |
| RAG | 先检索相关材料，再根据证据回答问题 |

例子：“订单 O1001 到哪了？”模型识别为物流问题，程序验证用户，再查订单和物流，模型将工具事实整理成易读答复。

知识问答：“拆封还能退吗？”先查演示政策，拿到具体版本的段落，再组织回答。检索不到就说明无法确认。第一版使用关键词检索，之后再根据失败样本决定是否加向量检索。

要记住：模型不是订单数据库，模型说“已退款”不等于退款真的发生。程序应该根据工具结果显示真实状态；本项目只处理模拟申请单。

练习目标：模型给出不存在的工具名、负预算或另一用户 ID 时，程序会拒绝或重新澄清，不直接执行。

## 10. 进程、异步和热插拔

进程是一个正在运行的程序。主 API 和物流插件分别运行在两个进程里，物流崩溃时主 API 仍能工作。端口是服务接收请求的编号；不同版本同时运行时需要不同端口。

异步处理用于等待网络或数据库时让程序还能处理其他工作。`async` 和 `await` 是 Python 中实现这种协作的语法；不是写上 async 所有代码就自动更快。到写 HTTP 客户端和插件管理时再学习。

热插拔是程序运行时接入、停用或替换插件。关闭物流插件时，先不接新任务，再等已有任务结束，这叫排空。升级时先启动新版、检查它、切换新请求，旧版处理完已有请求再退出。

版本切换失败时保留或恢复已验证旧版本，这叫回滚。必须考虑在途请求和数据兼容；数据库结构发生不兼容变化时不能随便回滚代码。

练习目标：持续运行主 API，关闭物流，新请求提示不可用，商品还能查；恢复物流后下一条请求重新可用。关闭整个主程序再启动不算插件热插拔。

## 11. 测试和日志

测试是一组可重复执行的检查。例如给定预算 100 元，预期只得到鼠标。日志记录程序做了什么、用了多久、为什么失败。

给每次请求一个 request_id，主程序与插件日志都带上它，方便追踪。不要把完整密钥写进日志。测试应包括正常情况和失败情况，尤其是越权、重复确认、超时和模块停用。

pytest 是自动执行 Python 测试的工具，官方入门包含创建并运行测试的步骤。[pytest 官方入门](https://docs.pytest.org/en/stable/getting-started.html)

练习目标：先手工验证商品筛选，再为真实业务边界添加自动检查。学习代码可以改来练习，正式代码修改后要重新验证相关业务。
