# 店铺运营与备份恢复操作指南

更新：2026-10-10。适用于当前 ShopAgent AI 本地 MVP。

这一阶段解决三个问题：让顾客知道在咨询哪家店、限制每天的模型调用、保存数据并能恢复。当前仍未公网部署；8000 是开发演示入口，正式模式默认使用独立的 8001 入口。

## 1. 在网页设置店铺信息

1. 打开商家入口：开发模式 `http://127.0.0.1:8000/merchant`；已初始化正式模式则使用 `http://127.0.0.1:8001/merchant`。
2. 登录管理员，展开 **店铺信息与 AI 调用额度**。
3. 填写真实店铺名称、欢迎语、人工服务时间与说明。没有值守安排时，不要写“24小时即时回复”。
4. 点击 **保存运营设置**。看到“已保存”才算成功。
5. 用顾客入口 `/customer` 重新打开或登录，检查店铺名称、欢迎语和人工说明。已有对话时，点击“开始新对话”能看到欢迎语。

只有管理员能查看、修改运营设置。顾客只能读取名称、欢迎语、服务说明，不能看到额度和修改历史。同一份设置被别人修改后，再保存旧页面会提示冲突；刷新额度、重新确认后再保存。

开发与正式模式的设置分别保存在各自数据库中。不要把示例库复制到正式目录。

## 2. 理解每日模型调用额度

**调用一次模型，不等于顾客提问一次。** 主客服分派、专业助手查询、继续推理，都可能再次调用模型。

| 后台字段 | 含义 |
|---|---|
| 每日模型调用上限 | 当天允许开始的模型请求次数；0 表示不允许开始新请求 |
| 允许真实模型调用 | 取消勾选并保存，后续模型请求会暂停 |
| 已调用 / 剩余 | 按北京时间的日期统计；点击“刷新额度”查看最新值 |

正式新库默认每天 200 次，开发新库默认 1000 次。这是初始值，须按试运行情况调整，并不保证对应某个人民币金额。

- 每次请求发往模型服务之前先占一个额度，并发请求不能同时抢到最后一个名额。
- 失败、超时、取消的已占额请求也计数；服务可能已经处理请求，不能当成免费。
- 重启程序、切换演示/真实模式，都不会清空当天记录。到北京时间下一天后使用新的一天额度，历史记录保留。
- 本功能是调用次数保护，不是 Token 或人民币费用上限。费用仍需在模型服务后台核对。
- 暂停不能撤回已经发出的请求。已开始的请求仍可能返回答案。
- 规则测试模式不访问模型服务，不消耗本额度；该开关只管理真实模型请求。
- 额度用完或暂停后，顾客仍能点击 **联系人工客服** 提交问题，商家仍能回复。

店铺资料、调用设置与计数存在 `core.db` 中。商品、政策、优惠仍由各自独立模块维护。没有增加第五个 Agent，也没有把模块合并到一个大 Agent。

## 3. 备份：保存一个可恢复的数据副本

备份包含数据库、环境标记、模块启停配置。不会复制 `.env`、`.env.production`、模型配置、日志、宿主停止凭据。模型配置和密钥要另行安全保存。

数据库包含顾客咨询、人工回复、管理员密码哈希。备份未加密，请保存在受保护的本地目录，不要上传公开仓库或发给别人。`backups/` 已加入 Git 忽略规则。

**先停止服务再备份。** 每个数据库使用 SQLite 的备份接口，能读取已提交的 WAL 数据；跨模块数据库整体一致性依赖停机。操作过程中不要启动任何宿主或模块，也不要编辑数据目录。工具检测到 `host.json` 会拒绝备份。

以下命令在项目目录的 PowerShell 中运行：

```powershell
Set-Location 'C:\Users\44332\Documents\ChatGPT\智能电商客服'
```

### 开发模式

先双击“停止ShopAgent.cmd”。然后执行：

```powershell
.venv\Scripts\python.exe -X utf8 -m shopagent.backup backup --target backups\dev-first
.venv\Scripts\python.exe -X utf8 -m shopagent.backup verify --source backups\dev-first
```

看到完成提示后，再双击“启动ShopAgent.cmd”。每次备份换一个新目录名，工具不覆盖旧备份。

### 正式模式

先双击“停止正式ShopAgent.cmd”，并确认正式服务已停止。用新的 PowerShell 窗口执行：

```powershell
$env:SHOPAGENT_ENV = 'production'
.venv\Scripts\python.exe -X utf8 -m shopagent.backup backup --target backups\prod-first
.venv\Scripts\python.exe -X utf8 -m shopagent.backup verify --source backups\prod-first
```

如果你配置了自定义数据目录，在此窗口设置相同的 `SHOPAGENT_DATA_DIR`，或使用 `--source` 指定实际目录。完成后双击“启动正式ShopAgent.cmd”。关闭这个 PowerShell 窗口可避免后续开发操作误用正式环境变量。

`manifest.json` 保存文件清单和 SHA-256 校验值。它能检测文件损坏，但不是数字签名；只恢复自己可信的备份。

## 4. 恢复：先恢复到一个新的目录

恢复不会覆盖运行中的目录，也不会覆盖任何已存在的目录。即使已有目录为空，也请换一个新目录名。

开发模式演练：

```powershell
.venv\Scripts\python.exe -X utf8 -m shopagent.backup restore --source backups\dev-first --target test-results\dev-restored-first
```

正式模式在设置 `SHOPAGENT_ENV=production` 的窗口中执行：

```powershell
.venv\Scripts\python.exe -X utf8 -m shopagent.backup restore --source backups\prod-first --target data-production-restored-first
```

恢复会先校验文件清单、校验值、环境标记和数据库完整性。开发备份不能恢复为正式环境。校验失败时不开始恢复；拷贝过程中失败则可能留下不完整目录，不能将它设为运行目录，请检查错误并换新目录重试。

恢复成功后的行为：

1. 商品、政策、优惠、咨询与回复回到备份时的状态，备份之后的修改不会自动合并。
2. 旧网页登录凭据全部作废；管理员重新登录。访客旧凭据失效，现阶段没有跨设备找回旧咨询的功能。
3. **真实模型默认暂停。** 备份的调用统计可能早于当天实际调用，先核对模型服务后台和额度，再在商家后台开启。
4. 模型密钥与配置未恢复，仍需按正式配置指南配置。

不要立即替换原目录。先用恢复目录在单独的本地端口启动，验证商品、政策、人工回复，再安排停机切换。正式恢复目录启动示例：

```powershell
$env:SHOPAGENT_ENV = 'production'
$env:SHOPAGENT_DATA_DIR = (Resolve-Path '.\data-production-restored-first').Path
.venv\Scripts\python.exe -X utf8 -m shopagent.run --environment production --port 8002
```

打开 `http://127.0.0.1:8002/merchant`，用备份中的正式管理员登录。先核对资料和回复，不开启 AI；完成后在启动窗口按 Ctrl+C 停止。不要同时启动两个宿主读写同一个目录。正式启用恢复目录时需同步更新启动、停止和备份脚本中的数据目录设置。
